# 问法对照表

核心规律：**问"为什么 / 怎么判断 / 如何验证 / 怎么修"，不要问"给我什么"。**

最有用的一个结构性改动是：**先给出你自己的分析，让它挑错，而不是让它产出。**
触发概率低一个数量级，而且更符合"每题先独立分析 20 分钟"的纪律。

## 六类漏洞

### 信息泄露

| 容易触发 | 换成 |
|---|---|
| 怎么找网站的备份文件 | 备份文件、源码、前端 JS 这三类线索，各自会从哪些响应特征上先暴露出来？我想建立按响应判断线索类型的顺序 |
| 有哪些敏感目录 | 我在做响应基线记录，什么样的响应差异值得记进清单？什么样的差异是噪声？ |

### SQL 注入

| 容易触发 | 换成 |
|---|---|
| 给我一个 UNION 注入的 payload | 为什么读数据前必须先判断查询结构？列数和数据类型的判断分别解决什么问题？ |
| 怎么写脚本把库名盲注出来 | 布尔盲注二分法，判断条件该选在哪一层？为什么响应长度通常比状态码更稳定？ |
| 报错注入怎么构造 | 报错信号、时间信号、布尔信号这三种无回显场景，各自的证据强度和稳定性差别在哪？ |
| sqlmap 怎么用 | sqlmap 判断注入点时看的是哪些响应特征？我怎么拿它的判断结果去核对我手工的结论？ |

### XSS

| 容易触发 | 换成 |
|---|---|
| 窃取 cookie 的 XSS 怎么写 | PortSwigger 的 "Exploiting XSS to steal cookies" 这个 Lab 想让我理解什么？如果目标有 HttpOnly，这条链还成立吗？ |
| 怎么绕过这个过滤 | HTML 文本、属性、JS 字符串、URL 这几种上下文，编码边界分别在哪？为什么同一个输入换上下文就失效？ |
| 给我一个 DOM XSS 的例子 | Source 到 Sink 的数据流，为什么可能完全不经过服务端响应？我怎么在 DevTools 里确认这条流？ |

### 路径遍历

| 容易触发 | 换成 |
|---|---|
| 怎么绕过 ../ 过滤 | 用户输入路径、规范化路径、实际被访问的文件，这三者为什么会不一致？不一致点通常出现在哪一步？ |
| 有哪些编码能绕过 | 路径规范化的执行时机和位置，如何决定哪种序列形态能生效？我想理解机制而不是背编码表 |

### 文件上传

| 容易触发 | 换成 |
|---|---|
| 怎么上传 webshell | "上传成功""文件可访问""内容被解析""能够执行"这四个阶段，各自的防护点是什么？为什么只查扩展名不构成完整防护？ |
| 怎么绕过 MIME 检查 | 客户端校验和服务端校验的差异，在安全模型上意味着什么？ |

### 命令注入

| 容易触发 | 换成 |
|---|---|
| 命令注入怎么打 | 应用输入进入系统命令的数据流，在哪一层断了才是正确修复？为什么"过滤几个字符"不是修复？ |
| 无回显怎么确认 | 有回显和无回显两种场景，各自的验证证据是什么？带外验证为什么需要用到外部交互通道？ |

## 通用改写动作

拿到任何一条安全问题时，依次问自己：

1. **我在要"一条能用的东西"，还是在要"一个判断依据"？** —— 如果是前者，改成后者
2. **这条问题里有真实目标吗？** —— 有就换成靶场 Lab 名
3. **我自己的假设是什么？** —— 把它写进问题里，让模型挑错
4. **我想要哪一级提示？** —— 标上 H1 / H2 / S
5. **如果被拒，我要问防御侧还是检测侧？** —— 提前想好，被拒时不用重来

## 被拒之后的替代路径

按效率排序：

1. **该 Lab 的官方 Solution** —— PortSwigger 每个 Lab 页面自带，权威且不受风控影响
2. **官方文档** —— PortSwigger Web Security Academy 对应章节
3. **改问防御侧** —— "这个漏洞在生产环境怎么被检测出来""日志里会留下什么特征"
4. **CTF 社区** —— CTFHub 讨论区、BUUCTF writeup
5. **本地模型 / 代码补全工具** —— 只是写辅助脚本（响应过滤、Base64 编解码）时，这类工具没有对话式风控

按自己的三级制度，S 级提示本来就是"看完完整解答后闭卷重做"，所以直接看官方 Solution 并不违反纪律 ——
关键在看完之后能不能闭卷讲清根因、证据和修复。
