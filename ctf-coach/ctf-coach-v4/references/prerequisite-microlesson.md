# 先修微课生成规则

只讲当前 Lab 实际需要、且用户尚未确认掌握的知识。微课必须在要求用户构造请求、payload、命令或编码之前完成。

## 每项知识的讲解结构

1. 名称与用途。
2. 所在解析层，例如 HTTP、模板引擎、目标语言、标准库或 Shell。
3. 一个与当前 Lab 无关的最小示例。
4. 示例的输入、运行过程和预期结果。
5. 关键 token 的逐项含义。
6. 成功、失败和未触发时的可观察信号。
7. 版本、平台或方言边界。
8. 一句话说明该示例证明了什么，以及迁移时应保留的抽象关系。

## 非靶场示例要求

- 不得包含当前 Lab 的参数名、路径、文件名、账号、域名、目标命令、完整 payload 或解题顺序。
- 只演示当前知识点本身，不把多个知识点提前串成利用链。
- 使用姓名、商品列表、普通字符串、算术表达式或 `echo hello` 等无害数据。
- 不得产生删除文件、修改账号、访问网络或其他不必要副作用。
- 如果示例引入新的辅助语法，也要解释该语法，不得用未知知识解释未知知识。

## 不同知识的示例要求

### 模板语法

必须同时展示：

`模板文本 → 输入数据 → 渲染结果`

明确区分模板源码、数据对象和最终输出。

### 编程语言、模块或函数

必须同时展示：

`独立代码片段 → 运行位置 → 返回值或输出 → 可观察结果`

明确区分返回值、标准输出、标准错误和副作用。

### HTTP 与编码

必须同时展示：

`原始字符 → 编码结果 → 解码结果 → 负责解析的组件`

不得混淆 URL 编码、表单编码、HTML 实体、语言转义和 Shell 语法。

### 命令或 Shell

只使用无害、可逆的演示命令，并说明：

- 命令由哪个系统上的 Shell 解释；
- 命令输出出现在哪里；
- 退出状态是否等于标准输出；
- Unix Shell、PowerShell 或其他平台的语法差异。

## 微课交付与非阻断验收

### 微课交付完成

进入 H2 前，必须完整给出每项新知识的：

- 名称、用途、所在解析层；
- 与本 Lab 无关的最小示例；
- 示例输入、运行过程和正确结果；
- 关键 token 的含义；
- 成功、失败与未触发信号；
- 版本、平台或方言边界；
- 与本题相关的抽象迁移关系。

不得把示例答案、预期输出、关键解释或后续教学内容留作用户回复后的条件。

### 非阻断验收

微课讲完后，可以用一个简短问题检查理解，但验收不得成为继续教学的闸门：

- 可以先邀请用户自行预测，但必须在同一条回复中紧接给出正确答案和原因；不得等待用户回复、发送占位回复，或把答案留到下一轮。
- 用户回答正确，标记为“已验证掌握”；
- 用户未回答、要求继续或暂时跳过，标记为“待复验”，仍进入默认 H2；
- 用户回答错误，立即针对错误点补讲，再进入默认 H2；
- 不为每个语法点单独设置问答；优先使用一个覆盖多个知识点的综合小题。

“继续”“下一步”“先做 Lab”等表达，视为用户要求推进教学，不得被解释为必须先回答微课题目。

### 复验时机

待复验知识可以在以下位置再次确认：

- 用户提交原始请求、关键变异和响应证据时；
- 用户解释当前响应为何出现时；
- Lab 结束后的机制复盘中；
- S 级答案后的闭卷重做中。

复验用于定位需要补讲的知识，不得以阻断教学流程作为目的。
